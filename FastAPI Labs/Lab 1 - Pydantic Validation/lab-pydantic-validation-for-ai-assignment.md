## Answer Key & Explanations

### Exercise 1 Answer
*   **Status Code**: `422 Unprocessable Entity`.
*   **Explanation**: FastAPI uses `422` because the request is syntactically valid (proper JSON) but semantically invalid (fails business constraints like temperature bounds or missing keys). It is not a `500` because a validation error is a client-side error (bad request parameter), whereas `500` is reserved for unexpected server-side code failures.

### Exercise 2 Answer
*   **Explanation**: LLMs are non-deterministic and do not guarantee schema compliance. A model might return malformed JSON, return empty responses, or output incorrect datatypes. Validating output on the server boundary protects downstream clients (like front-end UIs or database ingestion scripts) from processing corrupt or incomplete replies.

### Exercise 3 Answer
*   **Payload**:
    ```json
    {
      "messages": {"role": "computer", "content": "What's the capital of France?"},
      "temperature": 0.7,
      "max_tokens": 150
    }
    ```
*   **Failed Field**: `messages -> role`.
*   **Reason**: The value `"computer"` violates the validation constraint `Literal["assistant", "user"]` defined on the `Message` model.

### Exercise 4 Answer
*   **Code**:
    ```python
    max_tokens: int = Field(ge=1, le=2048)
    ```
*   **Explanation**: `ge=1` enforces that the value must be greater than or equal to 1, and `le=2048` enforces that it must be less than or equal to 2048.
